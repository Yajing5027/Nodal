# Study, review and sharing

Start with one small question. Write down what quicksort does today, add the code tomorrow, then add mistakes to watch for and questions to practise. Your notes can grow with your understanding.

## Organize what you are learning

A Note can hold a course, a quiz or a topic. Each Section is an independent knowledge node: find it, review it, move it or reuse it in another note. Keep related ideas together, then split a section or note when that becomes useful.

Use headings, lists, tables, code, equations and images. Keep code indentation and mathematical notation intact. Put a source or figure where it is used. A technique used in one problem usually belongs in its explanation, rather than in a new tag.

If you collect your writing in Google Docs first, keep clear section headings and boundaries. Prepare the note content and practice file separately, and check equations, code, images and answers before importing. Google Docs does not sync automatically.

## Turn notes into questions

- **Flashcards:** a question on the front, with the answer and explanation on the back. Try recalling before revealing.
- **Multiple choice:** include the complete choices, correct answer and explanation.
- **Clozes and hidden passages:** hide the part you want to recall while keeping enough context.
- **Existing mathematical problems:** use the problem as the front, and its solution and annotations as the back.

In Practice, use Copy Prompt to prepare questions and Import JSON to add questions you have checked. The format is `nodal.practice.v1`. Keep the same card ID when updating an existing question so its progress stays attached.

Creating or importing practice questions does not start scheduled learning. Use **Start learning** for a question, or **Start learning & review** for selected questions, when you are ready. Previewing or revealing an answer alone never saves a grade.

Reading a note, revealing an answer and completing a Review are different actions. Choosing Forgot, Partial or Recalled in Review updates that prompt’s memory state and next review time. A section’s manual mastery rating is a separate self-assessment, not a review schedule.

## Exact review times

A review is scheduled for a specific date and time, rather than simply “today.” The normal review queue shows the prompt once that time arrives. You can also choose a prompt manually in Practice to review it early.

With Research recording enabled, the record keeps the due time at presentation, actual presentation time and their difference. A positive difference means late; a negative difference means early. An unfinished attempt is kept separately from a completed rating. Leaving or missing a session is not automatically counted as Forgot.

## Events: dates to keep in view

An event can be a contest, an exam or a weekly quiz. Choose a single date or a weekly repeat, link the relevant notes, and see events ordered by their next date.

In Events, choose New event, enter a name and date or weekday, and select its notes. Show on Today controls the home page reminder. Show days remaining controls the day count. A recurring event also shows its weekday, such as Every Wednesday.

Events are date reminders. Review plans remain separate; linking notes to an event does not automatically change each question’s review cadence.

## Save and restore

In Data & backup, Export full backup prepares one ZIP with notes, tags, maps, images, questions, current review states, review history, plans, Events and any collected research records. Check that the download was saved, then keep the file somewhere you control.

A normal backup preserves all results and schedules; it never clears progress.

Restore from backup replaces the working content and review state. Existing research records are merged and retained, with the restore recorded in the journal. Export the current version before reorganizing content or restoring an older backup.


## Research recording

Research recording is a separate collection you can start or stop. It keeps question presentations, reveals, selections, completed ratings, content changes and some scheduling context, and travels with a full backup. Stopping collection keeps existing records.

Collection starts when enabled; unrecorded past experiences cannot be recovered. Self-ratings describe what you think you recalled, not independently measured correctness. The application cannot automatically know about outside study or why you did not open it.

## Share your study progress

A full backup also contains a separate public study snapshot: current notes, maps, event dates and progress for each prompt. Raw responses, research events and recovery archives stay outside that snapshot.

Once the snapshot is published, Study progress shows its content and update time. Visitors see the published study state while their own notes and review data stay separate. After studying further, export a new backup for the next update.

This is publishing in batches, not live cloud sync. GitHub Pages, different local addresses and different browsers have separate working data. Updating website code does not automatically upload the browser’s learning records.
